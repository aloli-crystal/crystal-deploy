== Objectif

Shard Crystal en ligne de commande pour déployer des applications Marten ou Kemal
sur tout serveur POSIX (FreeBSD, Linux, etc.).
Style Capistrano : `releases/`, `current/`, `shared/`.

Simple, testable, extensible.

== Principes fondamentaux

. *Pas de valeur par défaut dans le dialogue* — l'utilisateur saisit tout explicitement.
. *Le `.env` local n'est jamais lu pour le déploiement* — il appartient au développeur.
. *`config/deploy.yml` est la seule source de vérité* pour l'infrastructure.
. *`env_vars.yml` (dans le shard) définit les règles fixes* : obligatoires et ignorées.
. *Multi-langue via fichiers `.yml`* — zéro dépendance, fallback sur l'anglais.
. *Extensible* — ajouter un registrar DNS ou un moteur DB sans toucher au cœur.

== Format de `config/deploy.yml`

[source,yaml]
----
app_name: mon-app
repo_url: git@github.com:user/mon-app.git
crystal_main: src/server.cr
keep_releases: 10
framework: marten          # marten | kemal

# Adaptateur de base de données (défaut: postgresql)
database: postgresql       # postgresql | sqlite | none

# Registrar DNS (optionnel — si absent, pas de gestion DNS)
dns:
  registrar: ovh           # ovh | (futur: gandi, cloudflare, etc.)
  zone: example.app

environments:
  staging:
    branch: staging
    host: staging.example.com
    user: deploy
    app_url: https://staging.mon-app.example.app
  production:
    branch: production
    host: prod.example.com
    user: deploy
    app_url: https://mon-app.example.app
----

NOTE: Le champ `env_vars:` a disparu de `config/deploy.yml`. Les règles des variables
sont centralisées dans `config/env_vars.yml` du shard.

== Format de `config/env_vars.yml` (dans le shard)

Ce fichier définit les règles fixes, indépendantes du projet déployé.
Il est versionné dans le shard et peut être surchargé par le projet.

[source,yaml]
----
# Variables toujours demandées lors du `init`, dans cet ordre.
required:
  - key: SECRET_KEY
    secret: true
    generate: hex64        # généré automatiquement si laissé vide

# Variables jamais demandées (injectées automatiquement ou dev-only).
skip:
  - MARTEN_ENV             # injecté depuis config/deploy.yml
  - MARTEN_ALLOWED_HOSTS   # injecté depuis config/deploy.yml
  - MARTEN_SOCKET          # injecté depuis config/deploy.yml
  - APP_HOST               # dev local uniquement
  - PORT                   # dev local uniquement
  - DB_NAME_TEST           # base de test locale
  # Les variables DB_* sont gérées par le dialogue `database`
  - DB_HOST
  - DB_PORT
  - DB_USER
  - DB_PASSWORD
  - DB_NAME
  - DATABASE_URL
----

== Déroulement du dialogue `init`

[source]
----
=== Configuration de l'environnement (.env) ===

[INFO] MARTEN_ENV           = staging
[INFO] MARTEN_ALLOWED_HOSTS = dev.mon-app.example.app
[INFO] MARTEN_SOCKET        = /tmp/.mon-app--staging.sock

--- Variables obligatoires ---
SECRET_KEY (généré automatiquement si vide) :

--- Base de données ---
Mode de connexion :
  1) Socket Unix
  2) TCP
Choix :
...

--- Variables optionnelles ---
Voulez-vous configurer les variables optionnelles depuis .env.example ? [O/n]

  Si O → pour chaque variable de .env.example non encore définie et non ignorée :
    SMTP_HOST — configurer ? [O/n/valeur directe]

--- Récapitulatif ---
SECRET_KEY          : ***
DB_HOST             : /var/run/postgresql
...

Confirmer et envoyer sur le serveur ? [O/n]
----

=== Règles de saisie

[cols="1,3"]
|===
| Situation | Comportement

| Variable `required` avec `generate`
| Génère automatiquement si l'utilisateur laisse vide

| Variable `required` sans `generate`
| Redemande jusqu'à obtenir une valeur non vide

| Variable optionnelle (depuis `.env.example`)
| Proposée avec `[O/n/valeur]` — `n` = ignorée, `O` = saisie demandée

| Variable `secret: true`
| Affichée comme `***` dans le récapitulatif

| Variable dans `skip`
| Jamais affichée ni demandée
|===

== Système de traduction (I18n)

=== Principe

[source,crystal]
----
# Détection automatique depuis la variable d'environnement LANG
# "fr_FR.UTF-8" → "fr" → charge locales/fr.yml
# Si le fichier n'existe pas → fallback sur locales/en.yml
lang = ENV.fetch("LANG", "en")[0, 2].downcase
----

=== Utilisation dans le code

[source,crystal]
----
I18n.t("init.section_env")
I18n.t("db.mode_socket")
I18n.t("errors.unknown_env", name: "staging")
----

== Interface DNS (extensible)

[source,crystal]
----
# dns/base.cr
abstract class CrystalDeploy::DNS::Base
  abstract def credentials_present? : Bool
  abstract def load_credentials : Nil
  abstract def ask_credentials : Nil
  abstract def save_credentials : Nil
  abstract def help_generate_keys(zone : String) : Nil
  abstract def create_cname(subdomain : String, target : String, zone : String) : Nil
end
----

La factory instancie la bonne classe selon `dns.registrar` dans `deploy.yml` :

[source,crystal]
----
DNS::Factory.for(config.dns_registrar, env, logger)
# → DNS::Ovh.new(...)
# → DNS::Gandi.new(...)   # futur
----

== Interface DB (extensible)

[source,crystal]
----
# db/base.cr
abstract class CrystalDeploy::DB::Base
  # Retourne un Hash avec les variables d'environnement construites
  # ex: {"DB_HOST" => "/var/run/postgresql", "DB_USER" => "mon_app", ...}
  abstract def run_dialog : Hash(String, String)
end
----

La factory instancie selon `database` dans `deploy.yml` :

[source,crystal]
----
DB::Factory.for(config.database, config, env, logger)
# → DB::Postgresql.new(...)
# → DB::Sqlite.new(...)    # futur
# → DB::None.new(...)      # pas de base de données
----

== Langues disponibles

Détection automatique depuis `LANG` (ex: `fr_FR.UTF-8` → `fr`).
Fallback automatique sur `en` si la langue n'est pas disponible.

[cols="1,2"]
|===
| Code | Langue

| `fr` | Français
| `en` | Anglais (fallback)
| `es` | Espagnol
| `de` | Allemand
| `pt` | Portugais
| `it` | Italien
| `nl` | Néerlandais (belge flamand)
|===

== Ce qui est conservé

* `generators/nginx.cr` — fonctionnel, testé
* `generators/rcd.cr` — fonctionnel, testé
* `generators/github_workflow.cr` — fonctionnel
* `ssh/client.cr`, `ssh/remote_runner.cr`, `ssh/remote_script.cr` — fonctionnels
* `commands/deploy.cr`, `rollback.cr`, `status.cr` — à compléter ultérieurement

== Ce qui est refactorisé

* `config.cr` — ajout `database`, `dns`, suppression `env_vars` (déplacé dans `env_vars.yml`)
* `commands/init.cr` — simplifié, délègue à `DB::Base` et `DNS::Base`
* `logger.cr` — intègre `I18n.t()` pour les messages
* `commands/ovh_setup.cr` — migré dans `dns/ovh.cr`

== Ce qui est supprimé

* `load_env_example` dans `config.cr` — remplacé par lecture directe de `.env.example` dans `init.cr`
* `EnvExampleVar` struct — supprimée
* `MARTEN_AUTO_VARS`, `TEST_ONLY_VARS`, `SHELL_COMMAND_PREFIXES` — remplacés par `env_vars.yml`
* `load_env_local` dans le dialogue init — supprimée (conservée uniquement pour les clés DNS)
